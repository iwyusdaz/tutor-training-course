## 1 · Evidence verification (complete)

Every factual claim in the training content was traced to a primary source before publication: the CALDER working paper 338-0426 (read in full, PDF), the Kraft/Schueler/Falken at-scale meta-analysis (read in full, PDF), NSSA's definition page and post-ESSER brief (read directly), and the dosage analysis press release (read directly, with the underlying report page located). Each source carries its URL and access date in [`research/evidence-notes.md`](../research/evidence-notes.md). **One plan-level claim was corrected during verification:** the at-scale effect is documented in the primary source as ~0.16–0.21 SD for large programs (and ~0.07 SD for virtual), not the 0.03–0.10 SD the build plan sketched — see the notes §1b for the exact quotes.

**Can show:** the content's claims trace to sources a reader can check. **Cannot show:** that the sources' own conclusions are correct (they are cited, not re-analyzed).

## 2 · Automated accessibility audit (complete)

Tool: axe-core 4.11.1 via the workspace audit script, WCAG 2.1 A/AA + best-practice rules, against every published page including the spot-the-move tool (audited in live-rendered states: initial, answered, feedback, results). Acceptance: **zero critical or serious violations**; anything moderate/minor is documented rather than hidden. Both content and code contrast choices (links, buttons, focus rings) were checked in the audit because the practice tool renders its own controls.

**Can show:** standards-conformance of the rendered DOM. **Cannot show:** real assistive-technology experience (see §7).

## 3 · Keyboard, reflow and focus tests (complete)

`evaluation/tests/keyboard-tests.mjs` serves `docs/` (or a built site via `--baseurl`) and drives headless Chromium keyboard-only: the practice tool is worked start to finish (radios reachable, Space to select, Enter to check, focus moves to the feedback heading, Next/Back/Start-over cycle, results table reached) at desktop and 320 px widths, with focus assertions after every state change and a no-positive-tabindex sweep. Reflow at 320 px is asserted for the practice tool (and for every content page when run against a built site; on raw `docs/` that check is recorded as SKIP, since Jekyll pages only exist post-build).

**Can show:** every scripted task completes with keyboard only, and focus is managed. **Cannot show:** how a real screen reader or switch user experiences it.

## 4 · Agent review (complete — in-session, with the limitation stated)

A structured review of every module, the transcripts, the practice tool and the coaching documents, using the fixed form ([design-review-form.md](human-protocol/design-review-form.md)): heuristic evaluation (Nielsen's set) + cognitive walkthrough. Findings were triaged; accepted fixes are recorded in [`CHANGELOG.md`](../CHANGELOG.md).

**Who reviewed it — stated exactly:** this review was performed **by the authoring agent itself, in the same session that built the repo** — not by a separate reviewer agent in a fresh context. The portfolio standard calls for a separate reviewer; that separate pass is queued as a post-publish step and will append its findings here and in the changelog. The transcript realism review (§5) has the same provenance.

**Limitation, stated plainly:** same-author review is weaker than independent review, and both may run on the same underlying model family — so nothing here is an independent expert review. Everything in §4–§5 is labeled **"Agent review"** everywhere it appears (never "educator review" or "expert feedback"). It cannot substitute for the practitioner review of transcripts or the pilot, both of which remain open to the owner.

## 5 · Transcript realism review (complete, single agent reviewer; panel pending)

The six fictional transcripts were reviewed against the misconception research they claim to depict (M1–M5, the [misconception bank](https://github.com/iwyusdaz/socratic-ai-tutor/blob/main/spec/misconceptions.md) and its sources): does each scripted student error match the documented behavior of the misconception it targets; do the tutor responses match the moves each transcript claims; is the pacing plausible for 30 minutes. The [realism-review form](human-protocol/realism-review-form.md) records the checklist; verdicts per transcript are in the form's results section.

**Pending:** a multi-model panel ([run-review-panel.mjs](run-review-panel.mjs), ≥2 models, agreement reported) and — the real validation — a practitioner (tutor/teacher) review, prepared in the human protocol. A realism review can find *inconsistency with the cited research*; it cannot certify that real classrooms sound like this.

## 6 · Simulated tutor-trainee runs + review panel (pipelines ready, pending)

`npm run eval:pending` runs both pipelines (MODEL_A produces; MODEL_B and MODEL_C review — a model never judges its own output):

- **`run-simulations.mjs`** — 9+ simulated trainees (3 personas × 3 experience levels, drawn from the build plan's learner personas: a college junior, a career changer and a community volunteer — all fictional) answer a pre-set of three scripted student errors, "study" the module content, then answer a parallel post-set. Responses are scored against the rubric's Domain 3 anchors by MODEL_B and MODEL_C independently (blinded to pre/post ordering), with agreement reported. **Descriptive statistics only** — simulated personas already know the content, so pre/post differences *cannot* be read as learning; the pipeline exists to surface ambiguous tasks, missing scaffolding and unrealistic error scripts.
- **`run-review-panel.mjs`** — MODEL_B and MODEL_C independently re-review all six transcripts for realism against the misconception research; verdicts and agreement are reported.

Safety rails (both pipelines): missing or placeholder `.env` values → exit 1 with a clear message and **zero network calls**; `--dry-run` exercises the full pipeline with stub responses into `dry-run/`, labeled **"DRY RUN – NOT REAL RESULTS"**, never cited as evidence; every prompt, response and setting is saved raw to `evaluation/output/` (gitignored) for reproducibility; the two committed summaries in `evaluation/results/` are regenerated for hand-committing after a real run, and a dry run never writes into `evaluation/results/`. `.env.example` matches the portfolio-wide model-slot format.

**Can show:** task clarity, scaffold gaps, realism flags — inputs to revision. **Cannot show:** learning gains, statistical significance, or "validated with users."

## 7 · Screen reader testing (not run — protocol prepared)

Automated VoiceOver control (Guidepup) does not function on the build machine's OS (macOS 27): the smoke test fails with "VoiceOver not supported." Per the portfolio's fallback rule, the substitutes are: the axe audit (§2), keyboard/focus tests (§3), and Playwright `ariaSnapshot()` accessibility-tree captures of the practice tool at every step ([evaluation/tests/aria-snapshot.mjs](tests/aria-snapshot.mjs), reviewed for names/roles/values; captures committed in `evaluation/tests/aria-snapshots/`).

**What has NOT happened:** any listening test with VoiceOver/NVDA/JAWS by automation or by a human, and no review by a daily assistive-technology user. The manual VoiceOver protocol ([voiceover-manual-check.md](human-protocol/voiceover-manual-check.md)) is written so the owner can run it in ~20 minutes. This absence is a standing limitation of the accessibility claims on this site.
