# Pilot protocol (prepared — not run)

Status: **protocol prepared, pilot not conducted.** Everything below is ready to use; when the owner runs the pilot, results go to the [pilot report](../../docs/evaluation/pilot-report.md). Nothing in this file may be presented as data.

## Goal

Test whether Modules 3–4 + the spot-the-move practice are **clear, usable, and plausibly helpful** for the target learner (a new math tutor) — and find concrete revisions. This is a usability/pilot test of materials, **not** an effectiveness study.

## Participants

- 3–5 adults who currently tutor, have tutored, or intend to tutor middle school math.
- Recruited by the owner from their own network or program partner sites.
- **Exclusions:** no minors; no one currently your employee/advisee (consent pressure).
- Remuneration per the owner's judgment; note it in the report.

## Ethics

- Written [consent](consent-text.md) before anything starts; consent covers purpose, recording (if any), quotes, withdrawal.
- **No personal data beyond an optional first name or initials**; response sheets carry a participant code, not a name.
- Data stored in one folder, deleted after the report is written, or anonymized into the report.
- The consent text explicitly says results may be published on this site only in anonymized, aggregate form.

## Materials under test

1. [Module 3 — questions, wait time and errors](../../docs/modules/3-questions-wait-time-and-errors.md)
2. [Module 4 — feedback and motivation](../../docs/modules/4-feedback-and-motivation.md)
3. [Spot-the-move practice](../../docs/transcripts/practice/index.html) (in-browser, nothing stored)

## Session flow (60–75 minutes, per participant)

| Minutes | Step | Notes |
|---|---|---|
| 0–5 | Welcome + consent | Read the consent together; answer questions; get signature |
| 5–12 | **Pre-task** | Written responses to the three scripted student errors — **set A** (below). No notes, no module access. Say: "answer as you would to a real student." |
| 12–35 | Study | Modules 3 and 4, self-paced. Participant thinks aloud if comfortable; facilitator records sticking points only (script: usability script) |
| 35–45 | Practice tool | Spot-the-move, all 10 exchanges, keyboard or mouse as they prefer |
| 45–52 | **Post-task** | Same instructions, three *new* errors — **set B** (parallel difficulty; same misconception mix) |
| 52–65 | Interview | Short survey + 3 open questions (below) |
| — | Close | Thank them; explain what happens next; note the withdrawal window |

## Task materials

**Set A (pre-task) — respond in writing, one or two sentences each, as you would to the student:**

1. *Student writes:* `x − 4 = 10 → x = 6`. *Student says:* "I moved the 4 over."
2. *Student writes:* `2(x − 4) = 2x − 4`. *Student asks:* "Is this right?"
3. *Student writes:* `4x = 12 → x = 12`. *Student says:* "I divided. Wait… did I?"

**Set B (post-task) — same instructions, new errors, same misconception mix:**

1. *Student writes:* `3x + 5 = 20 → 3x = 20`. *Student says:* "I subtracted the 5."
2. *Student writes:* `3(x + 2) = 12 → 3x + 2 = 12`. *Student says:* "I distributed."
3. *Student writes:* `4x + 2 = 14 → x + 2 = 3.5 → x = 1.5`. *Student says:* "I divided everything by 4."

**Parallelism rationale:** each pair targets the same misconception family (M2 sign-on-move · M3 distribution · M4 partial division), with set B phrased slightly less openly (participants are no longer cold). Difficulty ordering is fixed in advance so scoring is not gamed by task drift.

## Scoring (blind)

- Two scorers (the owner plus one colleague) score set A and set B responses with the [rubric's Domain 3 anchors](../../docs/coaching/observation-rubric.md), using the [blind scoring sheet](blind-scoring-sheet.md): sheets are shuffled, pre/post labels hidden, participant codes opaque.
- Descriptive reporting: per-participant anchor scores, any disagreement noted. **No averages presented as gains**; the report template enforces this.

## Interview questions (end)

1. What was most confusing, and what did you do at that moment?
2. Which part would you actually use with students, and which would you skip?
3. If you could change one thing about these two modules, what?

## Success criteria for the pilot

- ≥3 completed participants.
- Task completion without facilitator rescue: modules and tool navigable unaided.
- ≥3 concrete revisions identified from participant behavior or quotes — implemented and logged in the changelog, with the pilot cited.

## What this pilot cannot establish

Learning gains (n, no control, no delayed test), transfer to live tutoring (written responses, not live sessions), or anything about students. The report template's "can/cannot" table is part of the report, not a footnote.
