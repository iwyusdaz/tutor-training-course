# Program measurement

A training program nobody measures is a slide deck. This section is the fictional Bridge Math Tutoring program's measurement spine:

1. **[Measurement plan](measurement-plan.md)** — dosage, consistency, fidelity, tutor development, student progress, retention: every metric with its benchmark, source and cadence; leading-indicator rationale; equity check; privacy rules.
2. **[Simulated dashboard](dashboard-simulated.md)** — six schools of **simulated data**, including one school under-delivering dosage, each with an interpretation and an action plan. Labeled simulated throughout.
3. **[Onboarding timeline](onboarding-timeline.md)** — the fictional program's four-week new-tutor schedule (course content — not the build schedule of this site).
4. **[Alignment table](alignment-table.md)** — every training objective mapped to its module, practice, rubric row and fidelity metric. If a row can't be filled, the objective isn't trained, or isn't measured — that's the point of the table.

{: .note }
**Leading indicators on purpose.** Student outcomes lag and are noisy; implementation metrics (dosage delivered, sessions with an exit ticket, rubric scores) are early, fixable signals. The [research notes](https://github.com/iwyusdaz/tutor-training-course/blob/main/research/evidence-notes.md) carry the evidence for why implementation quality is where at-scale programs erode — the measurement system watches exactly those seams.
